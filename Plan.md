# EAGLE codebase improvement and study replication plan

Use the current Mininet experiment as a compatibility baseline, then close the gaps between that implementation and the study in separately verifiable steps. Preserve the binary supporting-switch actions, controller feedback loop, graph observations, and learning and evaluation entrypoints. Make every study result traceable to a topology, traffic scenario, checkpoint, metric definition, and set of runs.

The study reference is Monaco et al., *Adaptive SDN Autoscaling via Generalizable Multi-Agent Reinforcement Learning With EAGLE*, IEEE TNSM 23 (2026), pp. 6507–6522, DOI `10.1109/TNSM.2026.3717361`. Sections and figure numbers below refer to that paper. [Documentation.md](Documentation.md) describes the current execution path. The Python and runtime configuration establish current behavior where documentation differs.

Capture compatibility fixtures first. Develop the dependency extraction and topology work against those fixtures, then verify the live controller loop before running the learning protocol. Build the measurement path early enough to record the first curriculum run. Recover research inputs in parallel with the refactor so missing assets do not delay offline and synthetic verification.

## 2. Move the EAGLE model and policy out of the vendored library

The README identifies two EAGLE-specific files in the vendored tree. The installed DI-engine 0.4.9 distribution metadata contains neither filename. That supports extracting these classes as application code and testing them against an installed DI-engine. Compatibility of the framework APIs and wrappers remains to be demonstrated. [README library notes](README.md#ding) · [DEC_MAVAC](ding/model/template/dec_mavac.py) · [DecentralizedPolicy](ding/policy/decentralized.py)

1. Move the actor-critic model and policy into `model/` and preserve attribution. Make the model a regular PyTorch module with explicit state and output shapes. Keep framework-specific registration, collation, wrappers, and learning hooks in a small adapter. Replace the policy's relative imports from `base_policy` and `common_utils` with verified installed interfaces or a narrow adapter for the required behavior. Apply the same boundary to the Gym/DI-engine environment wrapper so the observation and reward code can be tested without importing the training stack.
2. Make model, policy, and environment registration explicit before configuration compilation. Align the `decentralized`, `dec_mavac`, and `multi_network` registrations with the config and model factory. The current policy's `default_model()` points to generic `mavac` while the main trainer constructs `DEC_MAVAC` directly. Keep one training entrypoint and one evaluation entrypoint with normal imports, usable outside their source directories. [Training entrypoint](model/train_decentralized.py) · [Experiment configuration](model/net_config.py) · [Environment registry](model/multi_env.py)
3. Preserve the 256/128/64 hidden widths and separate actor and critic weights per agent. State explicitly that the actor currently returns softmax probabilities under the `logit` key. Verify what the installed collection and evaluation wrappers consume, including sampling from the intended distribution, argmax behavior, and the batch and agent dimensions. Keep the reward estimator and consensus mathematics in EAGLE-owned code so they can be tested independently of the framework.
4. Restore the standard PyTorch `load_state_dict` interface and move legacy conversion into a separate loader. The existing override expects three dictionaries and pulls out `actor.N` and `critic.N` entries, while the policy's training restore passes one model state. Load a combined checkpoint once and map per-agent files by explicit controller identity when such files are available. Validate shapes, order, and exact key coverage. Save a new checkpoint with preprocessing parameters, actor and critic weights, reward estimators, optimizers, running reward averages, consensus and pruning progress, and the seed and curriculum position needed for a resume. 5. Verify the install-backed path in an isolated checkout with the vendored tree absent. Confirm framework modules resolve to the installed library and EAGLE classes to the application. Remove the full vendor tree only after those checks and a bounded Mininet run pass. ## 5. Implement and verify the paper's learning protocol

The current learner holds all agents' networks in one process, averages critics and estimator outputs there, and updates each estimator during learning. It has a disabled pruning branch and no parameter transport between agents in the inspected training path. The controller's peer traffic carries topology, a distinct part of the system. Preserve a deterministic in-process execution for numerical tests, then verify the message-based protocol for distributed results. [Current learner](ding/policy/decentralized.py#L139) · [Controller peer payload](ryu_controller/controller.py#L109) · [Training task](model/train_decentralized.py#L20)

1. **Make one learner update auditable against §V.** Represent each agent's actor, critic, reward estimator, optimizers, and running average reward μ explicitly. Define the batch contract for current state, joint action, next state, local rewards, and episode boundaries. Compare the critic TD target, μ update, estimator input and target, and actor advantage to Eqs. (20)–(31) on a hand-calculated batch. Investigate the existing reuse of the last agent's `mu_local` across all agents and the estimator's use of `next_obs` with actions multiplied by 100. Document the selected state/action representation and terminal versus time-limit treatment before changing it. Use the reported learning rates 0.0001 for the actor and 0.001 for the critic and reward estimator in the study configuration. [Learner update](ding/policy/decentralized.py#L139) · [Learning settings](model/net_config.py)
2. **Separate estimator pretraining from policy training.** Section V describes local estimator updates and consensus during learning. Section VI-A reports pretraining the estimator and using it in inference mode afterwards. Make this distinction explicit in run configuration and recover the dataset, batch schedule, and freeze point. Verify that the published experimental configuration freezes estimator weights during subsequent actor and critic updates. Expose the ongoing-estimator variant if needed for a method comparison or ablation, with the variant logged.
3. **Implement consensus over the active communication graph.** Exchange local embeddings and joint-action information in the order required by the control step. For training rounds, exchange only the critic, estimator, and μ contributions required by the selected protocol, with the actor kept local. Define round IDs, participant sets, mixing weights, and timeout behavior. Unit-test known weighted averages, permutation of arrival order, and one missing peer. Then compare the in-process implementation with multiple workers exchanging real messages over the same fixture. Keep inference free of model parameter exchange.
4. **Measure pruning of messages.** Implement L1 magnitude pruning on outgoing copies of eligible linear weights with the first layer preserved, and encode retained values and their positions. For the paper's dynamic setting, start after five communication rounds at 30% and increase to 70% over the configured schedule. Compare dense, static 70%, and dynamic payloads as in §VI-I. Test masks and reconstruction by parameter name, actual serialized byte counts, and local tensors before and after encoding. The current branch compares a layer object to an integer and averages parameter lists after pruning reparameterizes the weights. Replacing it is a behavior correction, with explicit tests for the intended result. [Current pruning branch](ding/policy/decentralized.py#L258)
5. **Make curriculum and zero-shot modes explicit.** Drive the five TrEnvs from scenario definitions and carry learning state across them. TrEnv 1 is uncongested, TrEnvs 2–4 place hotspots in selected subnets, and TrEnv 5 congests all three. Recover the exact hotspot schedule and progression. The training script currently runs a single configured environment with no curriculum driver. For target trials, load a source checkpoint in evaluation mode, keep its preprocessing and slot order fixed, and verify via state comparison that the run performs no optimizer steps or normalization fit. A new topology may change the number of nodes within a subnet while preserving the input and action contract. [Training entrypoint](model/train_decentralized.py) · [Fixed observation order](model/multi_env.py#L101)

**Exit check.** Seeded offline training, checkpoint resume, and frozen inference pass their fixtures. A bounded live curriculum run saves an evaluable checkpoint. The distributed path produces comparable numerical results under the same inputs and measures real serialized exchange volume.
