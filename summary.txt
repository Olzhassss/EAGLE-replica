Main idea -- autoscaling = activation/deactivation of switches and links to dynamically adapt resource consumption (computing power, bandwidth, energy) based on workloads and user demands.

1. Alleviate congestion -> resilience
2. Reduce carbon footprint, improve cost efficiency 

Why RL?
Uses real-time feedback to adapt, enabled by controllability + observability of SDN.

Current works limitations:
1. Most run on 1 centralized controller -> large input space & increasing propagation delay
2. RL-based solutions are tuned for training envs only, cannot adapt to arbitrary network envs.

Solution -- EAGLE:
1. Offline network partitioning algo based on Louvain method + custom objective metrics // which metrics?
2. Multiple controllers, all running a local agent. Local agents collaboratively learn a joint policy by sending each other pruned model weights and embeddings. Pruning for saving bandwidth.
3. Use graph embedding for generalizability: network topology and traffic patterns -> virtual graph -> low-dimensional embedding. Also reduces MARL overhead.

Results:
Allegedly outperforms other solutions

## Controller placement

Controller placement is a minimum k-median problem.
1. Partitioning
Paper says partitioning is via Balanced Cut, but actually modified Louvian.
Louvian uses "modularity" (measure of density of links), loops until "equal" density of links.
This algo outputs highly variable size subnets (communities), which is suboptimal. So it is customized to balance partition sizes:
Relocation is penalized for varied number of switches between subnets, and rejected if new partition exceeds hard-coded controller capacity.
2. Controller placement
Place to minimize average hop-distance b/w switches and controller node, where controller is placed on one of the switch nodes.

## RL
MDP M=<S,A,P,R>

State space:
1. Construct vsubgraph after monitoring subnet
2. Embed vsubgraph
3. Send local embedding to other agents and receive from them.
4. Concat all embeddings into Z
5. Normalize Z
6. State input = normalized Z.

Action space:
1 or 0 for each (controllable?) switch // So, action space depends on the network size? How it that adaptable?

Reward:
R = norm(Th) - a * norm(PC)
Th - throughput = avg for all flows at time t
PC - power consumption = sum(P_idle + P_dynamic * rate) for all switches
	P_idle - static consumption Watt // what value?
	P_dynamic - W/Mbps consumption per data rate
	rate - traffic rate
a - hard-coded to 0.5
Normalization to [0, 1]

### Architecture

Actor-Critic - Actor outputs action, Critic evaluates. Agents share critic params

## Graph embedding

Fixed-state representation via graph embedding, trained via curriculum learning.
Feather Graph algorithm.
Curriculum learning (domain incremental learning) -- start with easy training examples, then gradually increase difficulty.
Allows faster convergence, higher asymptotic performance, better generalization
Established offline, 5 network traffic conditions of increasing difficulty. // how exactly is this implemented?
